# `.deepx/` — DEEPX Runtime Integration Knowledge

This is the **integration layer** for the DEEPX dx-runtime knowledge system.
It does NOT duplicate content from the sub-project knowledge bases. Instead,
it provides cross-project routing, unified agents, and integration-specific
instructions for tasks that span both dx_app and dx_stream.

---

## Architecture

| Level | Path | Scope | When to Use |
|---|---|---|---|
| **dx_app** | `dx_app/.deepx/` | Standalone inference apps (Python/C++) | Developing in dx_app submodule alone |
| **dx_stream** | `dx_stream/.deepx/` | GStreamer pipeline apps | Developing in dx_stream submodule alone |
| **dx-runtime** (this) | `.deepx/` | Cross-project integration | Working across dx_app + dx_stream |

Each sub-project `.deepx/` is fully self-contained and works independently
when the submodule is cloned alone. This integration layer adds:

- **Unified routing** — a single context routing table that covers all task types
- **Cross-project agent** — a router that dispatches to the correct sub-project builder
- **Integration instructions** — build order, shared model paths, cross-validation
- **Unified memory** — common pitfalls tagged by domain, spanning both projects
- **Unified scripts** — validators and generators that operate across all three `.deepx/` directories

## Scripts — Audience and When They Run

The four scripts under `.deepx/scripts/` are **harness / knowledge-base
maintenance tools**, run by the engineer who develops and improves
`dx-agentic-dev` itself. They do **NOT** fire automatically when an
end-user-facing application generated by an agentic CLI fails at runtime.

| Script | Run by | When | What it validates |
|---|---|---|---|
| `validate_framework.py` | KB maintainer / pre-commit hook | After editing any `.deepx/` file | Internal consistency of `.deepx/` (link drift, missing references, cross-level integrity) |
| `validate_app.py` | KB maintainer / E2E test harness | When inspecting a generated app artifact | Whether a generated app follows the patterns the KB documents (5 IFactory methods, `app.yaml` fields, GStreamer pipeline patterns, …) |
| `feedback_collector.py` | KB maintainer (manual) | Step 3 of the `DX Suite Validator` agent workflow | Aggregates the heterogeneous outputs of the validators above into a unified set of KB-update **proposals** (`feedback_report.json`) |
| `apply_feedback.py` | KB maintainer (manual, after approval) | Step 4 of the same workflow | Applies engineer-approved proposals (`--approve FB-001,…`) to the actual `.deepx/` files |

### Two scenarios — what is and isn't in this loop

**❌ Scenario A — End-user's generated app fails at runtime (NOT this loop)**

1. An end-user runs an app generated by an agentic CLI → it fails (e.g.,
   `setup.sh` forgot to create a venv, raising `ImportError`).
2. The session output under `dx-agentic-dev/<session>/` keeps the failure log.
3. **None of these scripts fire automatically.**
4. The KB maintainer separately:
   - Aggregates failure patterns via the E2E autopilot analyzer
     (`.deepx/tests/agentic_analyzer/`), or
   - Reads issue reports manually,
   - Decides which `.deepx/` rule is missing or weak, then enters Scenario B.

**✅ Scenario B — KB maintainer audits the framework (this loop)**

1. Engineer edits something under `.deepx/skills/…` or `instructions/…`,
   then invokes the **DX Suite Validator** agent.
2. **Step 1** — `validate_framework.py` runs at all 3 levels → internal
   consistency check.
3. **Step 2** — `validate_app.py` runs against sample / reference apps →
   KB ↔ generated-app alignment check.
4. **Step 3** — `feedback_collector.py --all` → produces
   `feedback_report.json` with proposal IDs (FB-001, FB-002, …).
5. **Step 4** — Engineer reviews proposals and runs
   `apply_feedback.py --report … --approve FB-001,…` to apply only the
   accepted ones.
6. **Step 5** — Validators re-run to confirm the fix.
7. Finally, `dx-agentic-gen generate` propagates the KB changes to the
   platform files (CLAUDE.md, AGENTS.md, copilot-instructions.md, etc.).

### Boundary

- ✅ **KB / framework integrity** — covered by these scripts.
- ✅ **Generated app compliance with KB rules** — covered by `validate_app.py`.
- ❌ **Automatic remediation of end-user runtime failures** — NOT part of
  this loop. End-user runtime failures feed in only indirectly through the
  E2E autopilot analyzer (`.deepx/tests/agentic_analyzer/`), where the
  maintainer manually decides which findings warrant KB changes.

## Developer Workflow

```
1. Edit     →  Modify files in .deepx/ (this level or sub-projects)
2. Validate →  python .deepx/scripts/validate_framework.py
3. Generate →  dx-agentic-gen generate   (or: bash .deepx/tools/scripts/run_all.sh generate from suite root)
4. Commit   →  git add .deepx/ && git commit
```

All changes flow from `.deepx/` outward. Never edit generated platform
files directly — they will be overwritten on the next regeneration.
